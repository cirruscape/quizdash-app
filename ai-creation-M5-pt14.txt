2. BUILDING M6, AND CORRECTING THE PLAN
------------------------------------------------------------------------------

USER:
Continue to M6

[Claude read the bootstrap template before changing it. GitHub's deploy
 role can only drive CloudFormation, with "Resource: *", which already
 covers us-east-1. The resources themselves are created by a separate
 execution role, which already has the rights it needs.]

CLAUDE:
That probably means M6 needs no bootstrap change, so the plan was wrong
on that point.

[The plan had said the developer would need to redeploy the bootstrap
 stack. Claude corrected the plan rather than adding permissions that
 nothing needed.]

[A second correction came from reading the stacks. The web stack imports
 the API's address from the api stack, and CloudFormation won't change an
 exported value while another stack imports it. So CloudFront kept its
 existing route to the API, and api.{domain} was added alongside it for
 scripts and the smoke test. The app behaves the same, still with no
 CORS.]

[The www redirect lives in a CloudFront Function written inline in the
 template. It was built test-first: the test reads the function's code
 straight out of web.yaml and runs it, so the tested code is exactly what
 deploys. Red: no such code yet. Green: www redirects with a 301, keeping
 the path and query string, and app routes still get index.html.]

[The rest:
   - a us-east-1 certificate stack, because CloudFront accepts
     certificates only from there;
   - a regional certificate and custom domain for the API;
   - DNS records for every name;
   - every domain value read from infra/params/{env}.json on every
     deploy;
   - a pipeline step that checks the live site and the redirect.]

[Checks along the way:
   - cfn-lint gave a false-positive warning on the empty default
     certificate ARN. Claude added a real validation pattern, and
     suppressed the warning only on that one resource, with a comment.
   - The API mapping depends on a resource SAM generates. Claude ran the
     SAM transform locally to confirm the generated name, rather than
     trusting memory.
   - A GitHub job output is silently dropped if it contains a masked
     value, and the certificate ARN contains the account ID. Claude turned
     masking off for that one job.]

Observations worth blogging about:
  - The plan was corrected twice by reading the actual code: no bootstrap
    change was needed, and an export can't change while it's imported.
    Plans written before the code is read are hypotheses.
  - The cheapest permission change is the one you find you don't need.
  - Infrastructure logic got a real test by running the code taken out of
    the template, so the test can't drift from what deploys.
  - An alarm needed a metric, and the metric needed a domain decision: a
    refusal isn't a failure.
  - Sharing an account was an accepted trade-off. It brought its own
    checklist: names, tags, and a budget that doesn't count other
    workloads.
  - Claude kept the developer's email out of the repo and out of this
    write-up, even though it's used for alerts.
