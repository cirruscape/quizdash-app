2. RUNNING SPIKE B BY HAND: A GUIDED SESSION
------------------------------------------------------------------------------

USER:
Remind me how to do Spike B

[Claude wrote a step-by-step manual check for the four properties Spike B
 must prove against the live AppSync Events API:
   1. A Player can subscribe to their own Game's channel.
   2. The same Player is refused another Game's channel.
   3. The Player is refused publishing.
   4. An IAM publish from the backend's side reaches subscribers.
 The steps were: read the stack outputs and the signing secret with the
 AWS CLI; mint a Player token using the repo's own signPlayerToken
 function; connect with wscat; paste four protocol messages; and publish
 from the AppSync console with IAM. Each step had its expected reply, plus
 an optional teardown, with a reminder to also remove the pipeline job.]

Two shell problems came up on the developer's machine. Claude diagnosed
each one from the error text alone.

USER:
Running 1. above results in the following being displayed: -bash: !: event
not found >

CLAUDE:
That's bash history expansion. In an interactive shell, a "!" inside
double quotes means "recall a previous command". My snippet had one: the
TypeScript process.env.KEY!. The failed expansion also left the shell
waiting for the rest of the command, which is the ">" prompt.
[Claude gave a corrected version that uses single quotes and no "!".]

USER:
Now I get: Command 'pnpm' not found, did you mean: command 'npm' from deb
npm (9.2.0~ds1-2)

CLAUDE:
pnpm isn't installed on its own here. This repo runs it through Node's
corepack. The simplest fix is to skip pnpm and run the repo's local copy of
tsx directly.
[Claude gave the one-line change, explained "corepack enable" as the
 permanent fix, and noted that the apt npm suggestion hinted the terminal
 might be using a different Node from the one the repo needs.]

USER:
the token printed, what next?

[wscat can't read shell variables. So, instead of asking the developer to
 hand-edit long JSON, Claude gave a printf command that prints the four
 messages with the real token filled in. It gave a table of what to paste
 and which reply to expect for each, then the console steps for the IAM
 publish.]

USER:
all four checks passed

Lesson for the blog: the one check Claude couldn't safely automate, a live
