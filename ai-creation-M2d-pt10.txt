Creating a Quiz from a Topic in the web UI is M3. The design is already
settled in the PRD and PLAN §8:
 1. A "New quiz" form: a free-text Topic, a Difficulty, 5-20 Questions,
    and a default Time Limit.
 2. POST /api/quizzes checks the daily limit, saves a Draft Quiz marked
    "generating", and hands the work to a background worker, because
    generation takes tens of seconds.
 3. The worker invokes the AgentCore agent, with the Host's earlier
    Questions on similar Topics, so the agent avoids repeats.
 4. The agent generates the Questions, then verifies each one in a
    separate check, and regenerates any that fail. JSON comes back
    through Converse tool use, because Nova 2 Lite doesn't support
    Bedrock's native structured outputs (ADR 0005).
 5. A review screen: discard or regenerate single Questions, override
    Time Limits, then approve.
 6. Plain errors for refused Topics, and for hitting the daily limit.
My suggested order: finish today's hand test, then M3, then M2d.

3. M2d: GAME HISTORY, TEST-FIRST
------------------------------------------------------------------------------

[M2d used the seams already agreed for M2, so Claude didn't ask for new
 seam decisions. Each slice was red then green:]

  Domain
    - The Game keeps each revealed Question's Option counts, through to
      the end. Games stored before History existed have no such list
      yet, so the code tolerates its absence.
  Repository contract
    - A Host's History lists newest first, and stays private to that
      Host. It passed in memory AND against the real dev DynamoDB table.
      (Claude also folded two paged DynamoDB queries into one shared
      helper; the contract confirmed nothing changed.)
  Service
    - When a Game finishes, its History record is written before the
      Join Code and active-Game slot are released: the revealed
      Questions as played, the correct Options, the per-Option counts,
      and the final Leaderboard.
    - The list shows the winner and Player count.
    - Another Host's Game reads as "not found", so its existence isn't
      confirmed (FR-9.2).
  Router
    - GET /api/history and GET /api/history/{gameId}, for Hosts only,
      with HISTORY_NOT_FOUND mapped to 404. Both added to the API stack.

[The web app gained a "Past games" list (newest first, with the winner
 and Player count), a detail page (the final Leaderboard and each
 Question's counts, with the correct Option highlighted), and a "See this
 game's full results" link on the Finished screen.]
[The smoke test now checks after every deploy that History recorded the
 Game exactly as played.]
