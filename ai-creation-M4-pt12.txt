3. THE BLOCKLIST, AND A REAL NAME IT WOULD HAVE BLOCKED
------------------------------------------------------------------------------

[The matching was built test-first against made-up words, so the tests
 checked the normalising rather than the list: leetspeak, symbols, spacing,
 stretched letters. One test deliberately records the agreed trade-off,
 that "prudent" contains "rude".]

[Claude then wrote the real word list, with a guard test: common names and
 words must pass. It chose words carefully, leaving out "ass" (in
 "Cassie"), "cock" ("Hancock"), "arse" ("Arsenal") and "rape" ("grape"),
 and leaving those to Comprehend.]

[The guard test failed on its first run: "Shitij", a real given name,
 contains "shit".]

CLAUDE:
The guard test caught a real false positive straight away. "Shitij" is a
genuine given name, and it contains "shit". This is the Scunthorpe
trade-off at its worst, blocking someone's actual name, which is the kind
of mistake the guard test exists to catch. I'll drop "shit" from the list.
Comprehend's profanity category still catches it.

Lesson for the blog: the agreed trade-off (broad matching, rare false
positives) was right in principle. But a test using real-world names
showed where it would hurt real people, and the list was adjusted rather
than the people.

[Removed Players: the real-time authoriser now refuses a removed Player's
 token for new connections and subscriptions. Claude noted the platform's

[The abandonment sweeper, test-first:
   - repository contract: find unfinished Games idle since a cutoff,
     through the sparse index the table has had since M0. The test checks
     membership rather than an exact list, because the index is
     eventually consistent and the dev table holds Games from earlier
     runs.
   - service: Games idle 24 hours are abandoned through the normal path,
     so History, released claims and the GAME_FINISHED event all happen
     as usual; a Game with activity a minute before the sweep is
     spared. ]

[The service test then failed: zero Games abandoned, not one. The domain
 treats exactly 24 hours idle as abandonable; the repository lookup used
 "strictly before". The two layers disagreed about the boundary.]

CLAUDE:
The test caught a real boundary mismatch. I'll make the lookup inclusive,
meaning "last active at or before", so it matches the domain.

Observations worth blogging about:
  - A test that used real-world data ("does this name list pass?") caught
    a harm that the rule's own tests, which used made-up words, couldn't.
  - Two layers disagreeing about an edge case (exactly 24 hours) is the
    kind of bug that hides for months. Testing through the whole path,
    service plus repository, found it on the first run.
  - Claude noticed when a test passed for the wrong reason (the boundary
    case hadn't been updated yet) and didn't count it as a pass.
  - Fail-open was a deliberate, recorded product decision, not an
    accident of error handling.
  - Claude was explicit about what can't be tested quickly (a 24-hour
    sweeper) and said how it would be checked instead.
