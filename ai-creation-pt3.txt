[Claude checked three primary sources before writing anything:
   - the CloudFormation reference for AWS::BedrockAgentCore::Runtime
   - AgentCore's HTTP service contract: an arm64 container on
     0.0.0.0:8080, POST /invocations, and GET /ping returning
     {"status":"Healthy"}
   - AgentCore's documented execution role and trust policy
 It also read the Strands TypeScript SDK's README and type definitions
 from the installed package. That confirmed the BedrockModel options, and
 that AgentResult.toString() returns the reply text.]

[Claude made a model-specific choice: it left out "temperature", because
 Claude Opus 5.5 rejects sampling parameters, even though the Strands
 example sets one.]

[Claude wrote the Spike A agent:
   packages/agent/src/answerer.ts
       A Strands Agent using BedrockModel with au.anthropic.claude-opus-5-5,
       creating a fresh Agent per request so no history leaks between calls.
   packages/agent/src/server.ts
       AgentCore's HTTP contract, with request validation, a body size cap,
       and the model call injected so it can be tested without Bedrock.
   unit tests for ping, a successful invocation, bad bodies, model failure
       (500), and unknown routes ]

[A packaging decision: instead of "pnpm deploy" inside Docker, Claude
 bundled the agent with esbuild, the same approach as the Lambdas. The
 Dockerfile just copies one file, so building the arm64 image under
 emulation in CI stays fast. Docker isn't needed locally either.]

[The first bundle crashed at startup: Strands imports
 @modelcontextprotocol/client at load time, but Claude had marked it
 external. Claude then checked which of Strands' optional peer packages
 were actually installed, bundled those, and left out only the missing
 ones. It ran the bundle on its own with no node_modules: /ping answered
 Healthy, and a bad request got a 400.]

[Claude wrote infra/agent.yaml: an execution role following the AWS
 documentation, with Bedrock access scoped to the au. profile and Opus 5.5
 in Sydney and Melbourne (the profile routes between the two), plus the
 AgentCore Runtime pointed at the ECR image by commit SHA.]

[Claude extended the bootstrap deploy role. The pipeline can now invoke
 the agent for a smoke test, and read the artifacts bucket.]

[Claude made ci.yml reusable, so the deploy workflow calls it instead of
 both running on every push. It scoped CI's concurrency group by calling
 workflow, so the two can't cancel each other.]

[Claude wrote .github/workflows/deploy.yml. On every push to main:
   CI -> foundation stack -> agent image (arm64, pushed to ECR, skipped if
   this commit's image already exists) -> agent stack -> smoke test.
 The smoke test invokes the agent and expects "Canberra" in the reply.
 The Spike B stack deploys in parallel. Every job authenticates through
 GitHub OIDC, and CloudFormation creates resources through a separate
 execution role.]

[Claude looked up current versions of every GitHub Action used, and the

[Claude ran cfn-lint on all templates and actionlint on both workflows,
